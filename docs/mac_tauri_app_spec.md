# SuperBookScanner for Mac (Tauri 版) 仕様案

`docs/macos_support_spec.md` (C# 版を macOS に移植する案) に代わる案。C# にはこだわらず、Mac ネイティブで動く Tauri アプリとして作り直す。既存の C# 版 (Windows) はそのまま残す。

## 1. 目的と範囲

**本のページ画像 (スキャン・スマホ撮影) のフォルダから、読みやすく綺麗な PDF を作る Mac アプリ。**

| 範囲 | 機能 |
|---|---|
| 作る | 画像フォルダ入力、見開き分割、台形補正、傾き補正、**折り目 (ノド) の歪み補正**、影・照明ムラの除去、**AI 鮮明化**、余白の統一、PDF 出力、プレビューと手動調整 |
| 作らない (当面) | ページ番号の検出と、それを使った位置合わせ・ページラベル、OCR、PDF 入力 |

対象環境: Apple Silicon の macOS 14 以降。開発者の機体は MacBook Pro (ユニファイドメモリ 100GB 以上)。

## 2. 技術構成

```
Tauri 2
├─ フロントエンド: TypeScript + React (Vite)   … 画面、プレビュー、手動調整
└─ バックエンド: Rust
   ├─ crates/book-core   … 画像処理パイプライン (UI に依存しないライブラリ。CLI からも使う)
   ├─ crates/book-cli    … コマンドライン版 (動作確認・一括処理用)
   └─ src-tauri          … Tauri コマンド。book-core を呼び、進捗をイベントで UI に送る
```

### 2.1 画像処理: 純 Rust (OpenCV を使わない)

- `image` (読み書き)、`imageproc` (2 値化・大津法・適応的 2 値化・連結成分・モルフォロジー・ガウスぼかし・射影変換)、`nalgebra` (多項式近似・最小二乗)、`kamadak-exif` (EXIF 回転)、`rayon` (ページ並列)
- 理由: OpenCV は Mac での導入とアプリへの同梱が面倒。C# 版の歪み補正 (PR #1) が使う OpenCV の機能は、上記の crate と自前の双一次補間 (remap) ですべて置き換えられることを確認した
- 内部の画像は 1 ページ = RGB 8bit、長辺 3508px (A4 300dpi 相当) を基準にする

### 2.2 AI 鮮明化: Real-ESRGAN

- **第 1 段階: `realesrgan-ncnn-vulkan` を Tauri の sidecar (同梱する外部バイナリ) として呼ぶ。** 公式に macOS 版バイナリがあり、MoltenVK 経由で Apple Silicon の GPU で動く。Python も CUDA も不要
- 第 2 段階 (必要なら): Real-ESRGAN を ONNX に変換し、`ort` crate (ONNX Runtime) の CoreML 実行プロバイダで動かす。プロセス起動が不要になり、Neural Engine も使える。速度と画質を第 1 段階と比べて決める
- 倍率は 2 倍で処理し、出力の解像度に縮小する (C# 版と同じ)。モデルは `realesrgan-x4plus` を既定とし、設定で切り替えられるようにする

### 2.3 PDF 出力

- `lopdf` で、各ページの JPEG をそのまま (再圧縮せずに) 埋め込む。ページサイズは画像の px と DPI から計算する
- 見開き表示の設定: `/PageLayout /TwoPageRight` (1 ページ目を右側に表示)。縦書きの本は `/ViewerPreferences << /Direction /R2L >>` を設定 (自動判定はせず、UI で選ぶ)
- JPEG の品質は既定 85、カラーかグレースケールかは自動判定し、UI で上書きできる

## 3. 処理パイプライン (ScanTailor を参考に)

各段階は「自動で処理 → 結果をプレビュー → 必要なら手動で直す」の形にする (ScanTailor と同じ考え方)。手動で直した値はプロジェクトファイルに保存し、その段階から後ろだけを再処理する。

| # | 段階 | 自動処理の内容 | 手動調整 |
|---|---|---|---|
| 1 | 入力 | 対応形式は jpg/png/tif/webp/heic (heic は macOS 標準の `sips` で変換して読む)。ファイル名の自然順に並べ、EXIF の回転を反映する | 並び替え、除外、90° 回転 |
| 2 | 写真の平面化 | 学習済みモデル UVDoc (ONNX、tract で推論) で、紙の範囲・台形・反りをまとめて直し、机や指などの背景を落とす。見開きのまま行う | オン/オフ |
| 3 | 見開き分割 | 縦長の画像は 1 ページとみなす。横長の画像は、中央付近でノドの影と本文の空白列を探して 2 ページに分ける | 分割線をドラッグ、分割しない |
| 4 | 傾き補正 | 文字行の向き (投影プロファイルの分散が最大になる角度) から ±5° の範囲で補正する | 角度を入力 |
| 5 | **歪み補正** | PR #1 (`BookDewarp.cs`) のアルゴリズムを Rust に移植する。テキスト行をたどる → 多項式で近似 → 変位場を作る → 双一次補間で展開する。行が取れないときは本文ブロックの上端・下端の輪郭線を使う | オン/オフ、強さ |
| 6 | 影・照明ムラの除去 | 大きなぼかしで背景 (紙) の明るさを推定し、割り算して紙を白に揃える。ノドの影もここで消える | オン/オフ、強さ |
| 7 | AI 鮮明化 | 2.2 のとおり | オン/オフ、モデル |
| 8 | 余白の統一 | 各ページの本文の外接矩形を求め、奇数ページ・偶数ページそれぞれで中央値をとって、全ページを同じ大きさ・同じ位置に切り出す (ページ番号を使わない簡易版) | ページごとに矩形を調整 |
| 9 | PDF 出力 | 2.3 のとおり | 綴じ方向、品質 |

AI 鮮明化 (7) は時間がかかるので、プレビューでは 1〜6 と 8 の結果を先に見せ、7 は書き出し時に行う。

## 4. 画面

1. **ホーム**: フォルダをドロップ (またはフォルダを選択) → プロジェクトを作成。最近使ったプロジェクトの一覧
2. **ページ一覧**: サムネイルのグリッド。各段階の結果を切り替えて表示。警告のあるページ (分割の自信が低い、歪み補正できなかった等) に印を付ける
3. **ページ詳細**: 処理前・処理後の比較 (スライダー)。段階ごとの手動調整 (4 隅、分割線、余白の矩形)
4. **書き出し**: 出力先、綴じ方向、品質 → 実行。進捗バーとページ数・残り時間の目安

プロジェクトは入力フォルダ内の `_superbook/project.json` に保存する (段階ごとの設定・手動調整の値・中間画像のキャッシュ)。

## 5. リポジトリ構成

既存の C# 版と同じリポジトリの `mac/` 以下に置く。

```
mac/
├─ crates/book-core/   画像処理 (Rust)
├─ crates/book-cli/    CLI
├─ app/                Tauri アプリ (src-tauri + React)
└─ README.md           Mac での開発・ビルド手順
```

## 6. 進め方

| 段階 | 内容 | 確認方法 |
|---|---|---|
| M1 ✅ | `book-core` + `book-cli`: 入力 → 傾き補正 → 歪み補正 (移植) → 影の除去 → 余白の統一 → PDF | テスト画像で CLI を実行し、PDF を目視確認。Linux CI でもテスト可能 |
| M2 ✅ | AI 鮮明化 (ncnn sidecar)。余白の切り出し後のページだけを処理する | Mac で速度を計測 |
| M3 ✅ | Tauri アプリ: フォルダ選択、補正前後のプレビュー、書き出し | Mac で起動確認 |
| M4 | 写真の平面化 (UVDoc) ✅・見開き分割 ✅ + 手動調整の画面 | スマホで撮った見開き写真で確認 |
| M5 (任意) | ONNX + CoreML による AI 鮮明化、ページ番号の検出、OCR | |

M1 は Mac がなくても開発・テストできるので、ここから始める。M3 以降は Mac 上での確認が必要。

## 7. C# 版との関係

- 開発は Mac 版 (このディレクトリ構成) に絞る。C# 版 (Windows) は参考として残すだけで、今後は手を入れない
- 歪み補正は C# 版 PR #1 (閉じた) のアルゴリズムを移植したもので、今後は Rust 版 (`mac/crates/book-core/src/dewarp.rs`) を正とする
- リポジトリは AGPL-3.0。Rust 版も同じライセンスにする。ScanTailor (GPL-3.0) のコードは使わず、考え方だけを参考にする
